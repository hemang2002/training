☸️ Part C · The same app on Kubernetes in Day4_Docker_Kubernetes_Cloud/

C0 · Check the cluster, and give it your images

cd ..
kubectl get nodes
NAME                           STATUS   ROLES           AGE   VERSION
docker-desktop-control-plane   Ready    control-plane   28m   v1.37.0

Docker Desktop makes one of two cluster types. Kubeadm: the node is called docker-desktop and it already sees the images you built: skip to C1. kind: the node is called docker-desktop-control-plane and it runs in its own container with its own image store, so it can't see cifar-api:v1 (you'd get ImagePullBackOff). Copy your images into it once (PowerShell, ≈ 30 s):

foreach ($n in (docker ps --filter "label=io.x-k8s.kind.cluster" --format "{{.Names}}")) { foreach ($i in "cifar-api:v1","cifar-ui:v1") { docker save $i -o img.tar; docker cp img.tar "${n}:/img.tar"; docker exec $n ctr -n k8s.io images import /img.tar; docker exec $n rm /img.tar } }; Remove-Item img.tar
docker.io/library/cifar api:v1          	saved
Importing	elapsed: 5.4 s	total:   0.0 B	(0.0 B/s)
docker.io/library/cifar ui:v1           	saved
Importing	elapsed: 4.6 s	total:   0.0 B	(0.0 B/s)
docker exec docker-desktop-control-plane crictl images | Select-String cifar
docker.io/library/cifar-api                     v1                   fbd6eb10ac168       115MB
