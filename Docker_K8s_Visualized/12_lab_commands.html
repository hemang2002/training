A3 · Prove the layer cache works

Add an empty comment line at the end of api/app.py, save, and build again. Then remove the line again.

#12 [stage-1 5/6] COPY api/app.py api/model_service.py ./

👀 pip install … CACHED: only the code layer was rebuilt.

🧩 Part B · Two containers with Compose in ml-app/

B1 · Start API + UI together

docker compose up --build -d
docker compose ps
NAME           IMAGE          SERVICE   STATUS                  PORTS
ml-app-api-1   cifar-api:v1   api       Up (healthy)   0.0.0.0:5000->5000/tcp
ml-app-ui-1    cifar-ui:v1    ui        Up (healthy)   0.0.0.0:8501->8501/tcp

👀 Open http://localhost:8501 and predict a sample picture. Page 4.

B2 · See how the UI finds the API by name

docker compose exec ui python -c "import socket;print(socket.gethostbyname('api'))"
172.26.0.3
docker compose exec ui python -c "import urllib.request as u;print(u.urlopen('http://api:5000/health').read())"
b'{"status":"ok"}\n'

👀 The name api is a real address inside compose's network. (Optional: set API_URL: http://localhost:5000 in docker-compose.yml, docker compose up -d, and see "API not reachable". Then change it back.)

B3 · Stop the compose app

docker compose down
# removes both containers and the network; the images cifar-api:v1 and cifar-ui:v1 stay, Kubernetes uses them next

👀 Important: this frees ports 5000 and 8501 before Part C.
