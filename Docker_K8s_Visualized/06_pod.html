The Pod: the smallest thing Kubernetes runs

Kubernetes never runs a container "naked". It wraps it in a Pod: one (sometimes a few) containers that share one IP address and live and die together. A pod is like a disposable container with an address. When it dies, it's gone for good. That's why, on the next page, we let a Deployment look after pods for us.

👋 New here? The 30-second version

🧸 Think of it like this

A container is a person; a pod is the hotel room they get, with a room number (IP). People in the same room share it. When they check out, the room is cleaned and given to someone else with a new number.

👆 Do this

  1. Press kubectl apply and watch the STATUS column change.
  2. Press 💥 app crashes a few times in a row.
  3. Press 🗑 kubectl delete pod. Does it come back?

👀 Notice this

A crashed container is restarted in the same pod (RESTARTS goes up). A deleted pod is not recreated by anybody. Unless a Deployment owns it (page 7).

📖 Words, made easy:
Pod = container(s) + one IPREADY 1/1 = 1 of 1 containers ready for trafficRESTARTS = how often the container was restarted CrashLoopBackOff = keeps crashing, Kubernetes waits longer each timeImagePullBackOff = can't find the image

② What it looks like in YAML, and for real

  

    

      
# the simplest pod (for learning only: we never write bare pods in k8s/)
apiVersion: v1
kind: Pod
metadata:
  name: cifar-api
  labels: {app: cifar-api}     # a sticky note: used by Services (page 8)
spec:
  containers:
    - name: api
      image: cifar-api:v1
      ports: [{containerPort: 5000}]

      
Every Kubernetes YAML has the same four parts: apiVersion, kind (what it is), metadata (name, labels) and spec (what you want).

🗣️ Explain it like this

  
  1. "Kubernetes runs pods, not containers. A pod = our container + its own IP address."
    2. 
    
  2. "If the app crashes, the kubelet restarts the container inside the same pod. If it keeps crashing, it waits longer each time: CrashLoopBackOff."
    3. 
    
  3. "If a pod is deleted or its machine dies, nobody brings it back. So we never create pods by hand; a Deployment does it for us. Next page."






  
🧪 Try this (guess first!)

  
    
    
  1. Crash the app three times quickly. What happens to RESTARTS and STATUS?
      
    AnswerRESTARTS goes 1, 2, 3. After repeated crashes STATUS shows CrashLoopBackOff: Kubernetes waits 10 s, 20 s, 40 s… (up to 5 minutes) before trying again, so a broken app doesn't burn the CPU. Find the reason with kubectl logs <pod> --previous.
    2. 
    
  2. Apply with a wrong image tag.
      
    AnswerErrImagePull, then ImagePullBackOff: the kubelet can't find cifar-api:v2-typo anywhere. We saw exactly this in the real rollout test (page 7).
    3. 
    
  3. Delete the pod. Now what?
      
    AnswerIt's gone, for good. kubectl get pods says "No resources found". A bare pod has no owner to recreate it.
