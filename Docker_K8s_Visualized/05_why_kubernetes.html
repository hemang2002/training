Why Kubernetes? From one machine to a fleet

Docker Compose runs containers on one machine, and you are the one who fixes things at 3 am. Kubernetes (k8s) runs containers on many machines and fixes things itself. You write down what you want ("2 copies of the API, always") and Kubernetes keeps checking and correcting until reality matches.

👋 New here? The 30-second version

🧸 Think of it like this

A thermostat: you set 21 °C (what you want). It keeps measuring the room (what is) and switches the heating on or off to close the gap. You never tell it how. Kubernetes is a thermostat for containers.

④ Local vs Docker vs Kubernetes vs Cloud: which one, when?

These are not four competitors. Think of them as a ladder: each rung solves a problem of the rung below it, and costs more effort. Our course app climbs all of it: Day 3 runs it locally, Day 4 puts it in Docker, then on Kubernetes, then in the cloud.

💻

1 · Local

Run the Python files directly on your laptop.

python app.py
streamlit run ui.py
🐳

2 · Docker

App + Python + libraries packed in a container, on one machine.

docker compose up
☸️

3 · Kubernetes

Containers on many machines that heal and scale themselves.

kubectl apply -f k8s/
☁️

4 · Cloud

Someone else's machines, with a public URL. They can run your container, or even Kubernetes.

🤔 Which one fits? Pick a situation

💻 Local. You change code every minute: python app.py starts in a second. A container or a cluster would only slow you down now.
🐳 Docker. Send the image, not instructions: the same Python, libraries and model file run on every PC. No cluster needed for this.
☸️ Kubernetes (often a managed one in the cloud: GKE, EKS, AKS). Many copies on many machines, autoscaling, rolling updates, self-healing.
☁️ Cloud platform (PaaS): Render, Streamlit Community Cloud or Google Cloud Run. Push the code or image, get an https:// link. No server to look after. (Free tiers sleep when idle.)
🐳 Docker Compose on that one server. 400 requests a day is tiny. Kubernetes would be more work than the problem. Use restart: unless-stopped and a health check.

The rule of thumb: use the simplest rung that solves today's problem. Move up only when a real problem (crashes, traffic, many services) pushes you.

🗣️ Explain it like this

  1. "Compose runs on one machine and needs you to fix problems. Kubernetes runs on many machines and fixes them itself."
  2. "We don't give orders like 'start a container'. We write down what we want, and controllers keep comparing wanted vs actual and fix the difference, forever."
  3. "The brain (control plane) decides; the kubelet on each node does the work. Docker Desktop is a one-node cluster for learning."
  4. "Local, Docker, Kubernetes and Cloud are a ladder, not rivals. Local is for developing, Docker makes it run the same everywhere, Kubernetes keeps many copies alive, the cloud gives you machines and a public URL. Use the lowest rung that solves your problem."

🧪 Try this (guess first!)

  1. Untick "Controllers running", crash two containers, then tick it again.
    AnswerWithout controllers nothing happens: actual stays below desired, just like a server where nobody is watching. As soon as the loop runs again, it sees the gap and starts new copies. Kubernetes is only "self-healing" because of these loops.
  2. Kill node 2. Where do its pods come back?
    AnswerOn node 1: the scheduler only places pods on healthy nodes. (In a real cluster, it takes about 5 minutes before pods on an unreachable node are replaced: that's the 300 s toleration you'll see in kubectl describe pod.)
  3. Set replicas to 0.
    AnswerAll copies are removed: the desired state is "none". Nothing is broken; you asked for it. This is how you pause an app without deleting its configuration.
  4. In ④: is "Cloud" instead of Docker and Kubernetes, or on top of them?
    AnswerOn top. The cloud is where it runs, Docker and Kubernetes are how. Render and Cloud Run run your Docker image; GKE / EKS / AKS are Kubernetes run by the cloud provider. Our Day-4 Render deploy uses the same Docker image we built locally.
