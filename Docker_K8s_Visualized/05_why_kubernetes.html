Why Kubernetes? From one machine to a fleet

Docker Compose runs containers on one machine, and you are the one who fixes things at 3 am. Kubernetes (k8s) runs containers on many machines and fixes things itself. You write down what you want ("2 copies of the API, always") and Kubernetes keeps checking and correcting until reality matches.

👋 New here? The 30-second version

🧸 Think of it like this

A thermostat: you set 21 °C (what you want). It keeps measuring the room (what is) and switches the heating on or off to close the gap. You never tell it how. Kubernetes is a thermostat for containers.

🗣️ Explain it like this

  1. "Compose runs on one machine and needs you to fix problems. Kubernetes runs on many machines and fixes them itself."
  2. "We don't give orders like 'start a container'. We write down what we want, and controllers keep comparing wanted vs actual and fix the difference, forever."
  3. "The brain (control plane) decides; the kubelet on each node does the work. Docker Desktop is a one-node cluster for learning."

🧪 Try this (guess first!)

  1. Untick "Controllers running", crash two containers, then tick it again.
    AnswerWithout controllers nothing happens: actual stays below desired, just like a server where nobody is watching. As soon as the loop runs again, it sees the gap and starts new copies. Kubernetes is only "self-healing" because of these loops.
  2. Kill node 2. Where do its pods come back?
    AnswerOn node 1: the scheduler only places pods on healthy nodes. (In a real cluster, it takes about 5 minutes before pods on an unreachable node are replaced: that's the 300 s toleration you'll see in kubectl describe pod.)
  3. Set replicas to 0.
    AnswerAll copies are removed: the desired state is "none". Nothing is broken; you asked for it. This is how you pause an app without deleting its configuration.
