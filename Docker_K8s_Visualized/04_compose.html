Docker Compose: several containers as one app

Our app has two containers: the API (the model) and the UI (the web page). Typing two long docker run commands every time is painful. docker-compose.yml describes both in one file, and docker compose up starts them together on a private network where they find each other by name.

👋 New here? The 30-second version

🧸 Think of it like this

A band plays from one set list instead of each musician getting separate instructions. And on stage they call each other by name ("api!"), not by seat number.

👆 Do this

  1. In ①, press 🖼️ Predict with API_URL=http://api:5000.
  2. Change it to http://localhost:5000 and predict again.
  3. In ②, switch off depends_on and start the app.

👀 Notice this

Inside a container, localhost is the container itself. To reach another container, use its service name. Compose's built-in DNS turns api into an address.

① Two containers, one network

# ml-app/docker-compose.yml (shortened) services: api: build: {context: ., dockerfile: api/Dockerfile} image: cifar-api:v1 ports: ["5000:5000"] ui: build: {context: ., dockerfile: ui/Dockerfile} image: cifar-ui:v1 ports: ["8501:8501"] environment: API_URL: http://api:5000 # the SERVICE NAME depends_on: api: {condition: service_healthy}
🌐 network "ml-app_default" (made by compose)
🖥️ uiport 8501
→
🧠 api172.26.0.3 · port 5000
Press 🖼️ Predict.

② Who starts first? depends_on: service_healthy

The API needs ≈ 5 s to load its models. If the UI starts first, its first requests fail. depends_on with condition: service_healthy tells compose: "start the UI only after the API's HEALTHCHECK says healthy".

③ The commands you'll use

Real output (trainer's PC, some columns shortened)
docker compose up --build -d
# builds both images if needed, then starts api and ui in the background
docker compose ps

docker compose exec ui python -c "import socket;print(socket.gethostbyname('api'))"
172.26.0.3     ← compose's DNS turned the name "api" into the API container's address

b'{"status":"ok"}\n'
docker compose logs -f ui

docker compose down
# stops and removes both containers and the network (images stay)

The container names ml-app-api-1 = project (folder) name + service name + number.

🗣️ Explain it like this

  1. "Compose = one file that describes all the containers of an app. docker compose up starts them all."
  2. "Compose puts them on a private network. Containers talk to each other by service name: the UI calls http://api:5000."
  3. "localhost inside a container means that container itself: the most common beginner bug."

🧪 Try this (guess first!)

  1. Why does http://localhost:5000 work in your browser, but not as the UI's API_URL?
    AnswerYour browser runs on your PC, and compose opened the door 5000 on your PC (ports: "5000:5000"). The UI runs inside its own container, where localhost is the UI container: nothing listens on 5000 there.
  2. What is still missing that we'll need in production?
    AnswerCompose runs on one machine. If that machine dies, everything is down; there's no automatic spreading over many machines, no automatic scaling, no zero-downtime updates. That's Kubernetes (next page).
