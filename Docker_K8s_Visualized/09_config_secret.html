ConfigMap, Secret, Namespace: settings outside the image

Rebuilding an image just to change a setting is slow and risky. A ConfigMap keeps settings (like DEFAULT_MODEL=int8) outside the image and hands them to the pods as environment variables, like -e in Docker. A Secret does the same for passwords. A Namespace is a folder that groups everything of one app.

👋 New here? The 30-second version

🧸 Think of it like this

A coffee machine (the image) doesn't change; the order slip next to it (the ConfigMap) says "large, no sugar". Change the slip, not the machine. The Secret is the same slip, but in an envelope… that anyone with access can open.

👆 Do this

  1. In ①, change the ConfigMap to fp32. Do the pods change?
  2. Press rollout restart.
  3. In ②, type a password and see what a Secret really stores.

👀 Notice this

Pods read environment variables when they start. Changing a ConfigMap doesn't touch running pods: you roll them (restart) to pick it up.

ConfigMap cifar-config

# k8s/01-configmap.yaml apiVersion: v1 kind: ConfigMap metadata: {name: cifar-config, namespace: ml-demo} data: DEFAULT_MODEL: "int8" WORKERS: "1" # in k8s we scale with pods, not workers THREADS: "4" # in 02-api-deployment.yaml, the container gets ALL of them as env vars: envFrom: - configMapRef: {name: cifar-config}

② Secret: for passwords and API keys

Works like a ConfigMap, but for sensitive values: Kubernetes keeps them separate, can restrict who reads them, and doesn't print them in describe. But inside, the value is only base64-encoded. That's a way of writing, not encryption.

kubectl -n ml-demo create secret generic cifar-secrets --from-literal=API_KEY=s3cret

      

    

    

      
# how the API container would read it (k8s/extras/secret-example.yaml)
env:
  - name: API_KEY
    valueFrom:
      secretKeyRef: {name: cifar-secrets, key: API_KEY}

      
  • Never put real secrets in git (not even as a Secret YAML).
  • Real teams add encryption at rest or an external secret manager (Vault, cloud secret managers, Sealed Secrets).
