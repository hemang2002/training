Backpropagation: who gets the blame?

Gradient descent needs the slope for every knob. Backpropagation is the trick that computes all of them in one backward sweep: the error is passed backwards through the network, and every knob learns how much of the blame is its own.

👋 New here? The 30-second version

🧸 Think of it like this

A football team lost 0–1. Who is to blame, and how much? The coach starts from the final score and walks backwards through the match, handing out blame to each player. Backpropagation does the same: it starts from the error and hands out blame to every weight.

👆 Do this

  1. Press Next ▶ 5 times. Blue numbers flow forward: that is the prediction.
  2. Press Next ▶ 6 more times. Red numbers flow backward: that is the blame.
  3. On the last step every weight moves a little, and the loss gets smaller.

👀 Notice this

Each red number tells a weight: "if you go up a little, the loss changes by this much". Negative red means go up; positive red means go down.

📖 Hard words, made easy:
Forward pass = compute the predictionBackward pass = compute the blame for each weightGradient (red) = the blame numberChain rule = multiply the blame along the path, step by step

🧩 Our tiny network: one neuron

Two inputs (x₁, x₂), two weights (w₁, w₂), a bias b, an activation function, and a squared-error loss:

z = w₁·x₁ + w₂·x₂ + b
a = activation(z)
L = (a − y)²

A real network is thousands of these neurons wired together. Backprop works the same way for all of them. Each small operation (×, +, sigmoid) only needs to know its own local slope.

Analogy: a relay of blame. The loss says "I am 0.04 too big". It tells the node before it, "if you go up by 1, I go up by this much". That node multiplies by its own local slope and passes the message on. Every node does the same, back to the weights. Multiplying slopes along the path is called the chain rule.

Blue numbers = values computed going forward. Red numbers = gradients (∂L/∂·) computed going backward.

🔬 What does a gradient mean? The nudge test

A gradient answers one question: "If I nudge this knob up by a tiny amount, how much does the loss change?" Let's check it by actually nudging.

🧪 Try this (predict first!)

  1. Which way? With the default numbers, before pressing anything: should w₁ go up or down to reduce the loss? Then step through and check the sign of ∂L/∂w₁.
    AnswerThe output a ≈ 0.80 is below the target 1, so we want a bigger. A bigger z gives a bigger a, and x₁ = 2 is positive, so a bigger w₁ gives a bigger z. So w₁ should go up. The gradient ∂L/∂w₁ ≈ −0.126 is negative, and the update w₁ − lr × (negative) makes w₁ bigger. ✔
  2. No input, no blame. Set x₁ = 0 and step to the end. What is ∂L/∂w₁? Why?
    Answer0. The multiply node gives w₁ the gradient × x₁, and x₁ = 0. If the input is zero, the weight had no effect on this prediction, so it gets no blame and does not change. (That's one reason we normalize inputs: features stuck near 0 learn slowly.)
  3. The dead neuron. Choose ReLU and set b = −3. Step through, then press "Train 20 steps". What happens to the loss?
    Answerz = 2(0.5) + (−1)(−0.3) − 3 = −1.7 is negative, so ReLU outputs 0 and its slope is 0. The chain rule multiplies by 0, so every gradient is 0 and the loss never improves. This is a "dead ReLU". If it happens to many neurons in a real network, they stop learning for good.
  4. Very wrong, barely learning. Sigmoid, set w₁ = 5 and target y = 0. The prediction is almost 1 (very wrong!). Look at ∂L/∂z and train 20 steps.
    Answerz ≈ 10.4 and the sigmoid is flat out there: its slope a(1 − a) ≈ 0.00003. Even though the loss is almost 1 (terrible), the gradients are tiny and 20 steps barely help. This is the vanishing gradient problem, and it's why modern networks prefer ReLU in hidden layers.
  5. Too eager. Restore defaults and set target y = 0.5. Train 20 steps with lr 0.5. Then try lr 10, then lr 20 (set y = 0.5 again each time). Compare the loss curves.
    Answerlr 0.5: the loss falls smoothly from 0.091 to almost 0. lr 10: it jumps up and down (0.09 → 0.24 → 0.16 → …) and never settles. lr 20: the first step is so big that z shoots far out, the sigmoid saturates, and the loss jumps to 0.25 and stays there forever. It's worse than where we started, and stuck in the flat zone from challenge 4. Backprop gives the direction; the learning rate decides how far to go.
  6. Believe the numbers. Copy the PyTorch code below into a notebook cell and run it. Do you get the same gradients as the red numbers?
    AnswerYes, to 4 decimals. loss.backward() does exactly this backward sweep for you, for millions of parameters at once.
