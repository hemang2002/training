Transfer learning: don't start from zero

Training a network from scratch needs lots of labelled examples. But a network that was already trained on a big, related dataset has learned useful features (edges, strokes, shapes). We can reuse those features and only teach it the new task: often with just a handful of examples. That's exactly what Day 2 does with MobileNetV2 (pretrained on ImageNet) for CIFAR-10. It is not always the right choice, and this page shows both sides.

👋 New here? The 30-second version

🧸 Think of it like this

Someone who already plays the guitar learns the ukulele in a weekend: fingers, chords and rhythm carry over. Someone who has never played anything needs months. But a guitarist doesn't learn the drums faster: skills only transfer to similar things.

👀 Notice this

With very few examples, the network that reuses pretrained features wins by a mile. With very different pictures, frozen features stop working and the network must adapt them (fine-tuning).

📖 Hard words, made easy:
Pretrained = already trained on a big datasetBackbone = the part that turns pixels into features Head = the last layer that makes the decisionFreeze = don't change these weights any more Feature extraction = frozen backbone + new headFine-tuning = keep training the backbone too, gently

① The big dataset: pre-training the backbone

Pre-training…

4,000 tiny grey pictures (10 × 10 pixels) of 8 kinds of shapes: lines in four directions, plus, cross, triangle and V. Each one is shifted, resized and covered in noise, so the network can't just memorise pixel positions. It must learn what a stroke looks like.

The network: 100 pixels → 32 → 32 → 8. The first two layers are the backbone; the last layer is the head that picks one of the 8 shapes. This is our small "ImageNet": lots of labelled pictures, trained once.

② What did the backbone learn?

The 32 neurons of the first layer: the pixel pattern each one looks for
👀 Each square shows one neuron's 100 weights as a picture: blue = "I want ink here", orange = "I want no ink here". Many look like pieces of strokes and edges: little detectors that are useful for any task with strokes in it, not only for these 8 shapes. Compare Lesson 10's kernels.

The head is task-specific: it only knows the 8 old shapes. But the backbone's features are general. For a new task we can:

  1. A · From scratchRandom weights everywhere, learn everything from the new examples only.
  2. B · Feature extractionKeep the pretrained backbone frozen 🔒, throw away the old head, train only a new head (33 weights).
  3. C · Fine-tuningStart from the pretrained backbone + new head, and keep training everything with a small learning rate.

③ A new task: tell + from ×. Three strategies race.

New task, new labels: the network has to answer "plus or cross?" The pictures are the same kind of noisy 10 × 10 images. All three networks see exactly the same training examples, and are tested on 600 new pictures they have never seen.

🧭 Summary: which strategy when?

SituationBest choiceWhat you saw on this page
Few labelled examples, pictures similar to the pretraining dataFeature extraction (freeze the backbone, train a new head)✅ 5 examples each: frozen features ≈ 90%, from scratch ≈ 48% (guessing).
More labelled data, similar picturesFine-tuning with a small learning rate (or still frozen)➖ 200 each: from scratch improves a lot, but the pretrained ones are still ahead.
Pictures that look different from the pretraining dataFine-tuning: the features must adapt❌ Inverted colours: frozen features stall; fine-tuning adapts and wins.
Completely unrelated data (e.g. audio spectrograms with an ImageNet model) and lots of itTry from scratch too, and compareFeatures only transfer to similar things.
Any fine-tuningUse a small learning rate, or train the head first❌ A big learning rate wrecks the pretrained features ("catastrophic forgetting").

Fine-tuning wins on Day 2 because CIFAR's 32 × 32 pictures look quite different from ImageNet's big photos, the same lesson as the inverted pictures in ③.

Three real-world rules

  • Same preprocessing. Feed the pretrained model exactly what it was trained on: ImageNet mean/std normalisation. Forgetting Normalize is like the inverted pictures: the features see "different-looking" input (Day 2 Lab Ex. 3: ≈ 90% → ≈ 30%).
  • Frozen BatchNorm needs eval(). Freezing weights doesn't stop BatchNorm from updating its running statistics in train() mode (Lesson 8).
  • Small learning rate for the backbone, or train the head first with the backbone frozen, then unfreeze.

🧪 Try this (guess first, then check!)

  1. Five examples. Press ✅ Only 5 examples each. Who wins, and by how much?
    AnswerA (from scratch) ≈ 48%: with 10 noisy pictures it basically guesses. B (frozen) ≈ 90%, C (fine-tuning) ≈ 65%. B trains only 33 weights on top of features that already know what strokes look like, so 10 examples are enough. We repeated this with 4 different sets of training examples: B won every time.
  2. More data. Press ➖ 200 examples each.
    AnswerA improves a lot (≈ 75%), because now it has enough examples to learn its own features, but it is still behind B (≈ 92%) and C (≈ 91%). The more labelled data you have, the smaller the advantage of pretraining. With millions of pictures, training from scratch can catch up.
  3. Different-looking pictures. Press ❌ Different-looking pictures. The backbone was trained on dark ink on a light background; now the ink is light on dark.
    AnswerB (frozen) drops to ≈ 74%: its features look for the wrong kind of pixels. C (fine-tuning) adapts them and reaches ≈ 89%, better than A (≈ 83%) because it still reuses the shape knowledge. When the new data looks different, fine-tune, don't just freeze. (Forgetting ImageNet normalisation on Day 2 is the same mistake.)
  4. Too hot. Press ❌ Fine-tuning with too big a learning rate.
    AnswerC falls from ≈ 65% (learning rate 0.001) to ≈ 60% (0.03), far below the frozen B (≈ 90%). The first big steps, driven by a random new head, overwrite the pretrained features before the head has learned anything: catastrophic forgetting. That's why fine-tuning uses small learning rates.
  5. Count the knobs. Look at "Weights trained" for A, B and C.
    AnswerA and C train all 4,321 weights; B trains only 33 (32 features + 1 bias). Fewer weights to learn from few examples = much less room to overfit (Lesson 7), and much less compute: MobileNetV2 feature extraction trains 12,810 weights instead of 2.2 million.

🐍 The same thing in PyTorch (Day 2, Notebook 01)

import torch.nn as nn
from torchvision.models import mobilenet_v2, MobileNet_V2_Weights

model = mobilenet_v2(weights=MobileNet_V2_Weights.IMAGENET1K_V1)     # pretrained backbone + old 1000-class head
model.classifier[1] = nn.Linear(1280, 10)                         # new head for 10 classes (random)

# B · feature extraction: freeze the backbone
for p in model.features.parameters():
    p.requires_grad = False
model.features.eval()                                             # keep frozen BatchNorm statistics fixed
opt = torch.optim.Adam(model.classifier.parameters(), lr=3e-3)

# C · fine-tuning: unfreeze and use a SMALL learning rate
for p in model.parameters():
    p.requires_grad = True
opt = torch.optim.Adam(model.parameters(), lr=1e-3)

On this page the backbone is a small MLP on 10 × 10 pictures; a real backbone is a CNN (Lesson 10) whose early layers learn edges and colour blobs, middle layers textures, and late layers object parts. The same three strategies apply.

🤔 Check yourself

  1. You have 300 labelled photos of 3 kinds of machine parts. Train from scratch or start from an ImageNet model?
    AnswerStart from the pretrained model: 300 photos are far too few to learn good features from scratch, and photos of objects are similar enough to ImageNet for its edge and texture features to help.
  2. Why does feature extraction train so much faster than fine-tuning?
    AnswerNo gradients are computed or applied for the frozen backbone: only the small head learns. (You can even compute the backbone's features once and reuse them every epoch.)
  3. Your fine-tuned model is worse than the frozen one. Name two likely causes.
    AnswerA learning rate that is too big (challenge 4), or too little data so the many trainable weights overfit. Also check that frozen BatchNorm layers are in eval() mode and the preprocessing matches.
