RNN & LSTM: models that read in order

A picture arrives all at once. Text does not: it is a sequence, and the order matters. "Dog bites man" is not news. "Man bites dog" is. An RNN (recurrent neural network) reads one word at a time and keeps a small memory of what it has read so far. An LSTM is an RNN with a better memory: little "gates" decide what to keep, what to write and what to forget.

👋 New here? The 30-second version

🧸 Think of it like this

You read a story with a tiny whiteboard next to you. After every word you update your notes: "the hero is Anna, she is angry". A plain RNN rewrites the whole board every word, so old notes slowly get smudged. An LSTM has an eraser, a pen and a cover: it chooses what to wipe, what to add, and what to show.

👀 Notice this

The same small network is used at every word. The memory is just a list of numbers. In a plain RNN the start of a long text fades away. The LSTM's "conveyor belt" (cell state) can carry it much further, but it costs about 4× the weights.

① Why order matters

The simplest way to turn text into numbers is a bag of words: throw all the words in a bag and count them. The order is lost. Pick a pair below. Both sentences use exactly the same words. Then press Next word ▶ to read them the way a person (or an RNN) does: left to right.

🤷 Same bag → a bag-of-words model must give A and B the same answer.
👀 The words are identical, only the order is different, and the meaning flips. To tell A from B, a model has to read in order and remember what came before. That memory is exactly what an RNN adds.

Bag of words is not useless: for "is this SMS spam?" words like free, win, £ already say a lot. A bag model (e.g. logistic regression on word counts) is a strong, cheap baseline. It fails when the order carries the meaning: negation ("not"), who did what to whom, and long-range references.

② The RNN: one small network, used again and again

An RNN has one small cell. At every word it takes two inputs: the new word xt and its old memory ht−1. It mixes them and writes a new memory ht. The arrow that goes back into the cell is the "recurrent" part. If you draw one copy per word, you get the unrolled picture on the right.

🧩 The one rule, in words

new memory = squash( a bit of the new word + a bit of the old memory )

  • W · xt: what does this word add?
  • U · ht−1: what do we carry over from before?
  • tanh: squash the result to −1…+1 so it can't blow up.
  • The same W, U, b at every word. So an RNN can read a 3-word or a 300-word text with the same small set of weights.

🎓 Detailed: the formula

h_t = tanh( W · x_t + U · h_(t−1) + b ) h_0 = 0 (a vector of zeros) answer = Linear( h_T ) ← only the last step

Sizes in Notebook 07: xt has 32 numbers (embedding), ht has 64. So W is 64 × 32, U is 64 × 64, b is 64: about 6,300 weights (PyTorch keeps two bias vectors), used at all 40 steps.

③ The problem: the memory fades

"The keys to the old wooden cabinet in my grandmother's kitchen are on the table." To choose are (not is), you must still remember keys (plural) from many words back.

In a plain RNN, the memory is multiplied by U and squashed by tanh at every word. That usually shrinks it a little each time, like a photocopy of a photocopy. The same happens backwards during training: the learning signal for word 1 is multiplied again and again and vanishes. The LSTM (④) adds a separate memory line where the old value is multiplied only by the forget gate f. If the network learns f ≈ 1, the memory passes almost untouched.

⚖️ So is LSTM always better? No. Both sides:

➖ Short sequences: plain RNN is fineA few words, like short SMS messages or 5 sensor readings: enough of word 1 is left. In our notebook the plain RNN already reaches 97.0% (LSTM 98.2%).
✅ Long dependencies: LSTM winsReviews, emails, sentences where word 30 depends on word 2. The plain RNN has forgotten; the LSTM's cell state still carries it.
❌ The price: ≈ 4× the weightsAn LSTM is like 4 RNN layers in one (3 gates + 1 candidate). Same sizes as the notebook (32 in, 64 memory): RNN 6,272 weights, LSTM 25,088. About 4× more maths per word, so slower, and more to overfit on tiny data.

On our small SMS dataset both models trained in ≈ 6 s on a CPU, so the extra cost was not visible. On large datasets and long texts it is.

🎓 Detailed: why "vanishing gradient"? Backprop through time multiplies one Jacobian per step: ∂h_T / ∂h_1 = ∏ (t = 2 … T) diag(1 − h_t²) · U If these factors are mostly below 1, the product shrinks like 0.85T → the weights hardly learn anything from early words. If they are above 1, it explodes (fix: gradient clipping, torch.nn.utils.clip_grad_norm_). In the LSTM, the path along the cell state is ∂ct/∂ct−1 = ft, with no U and no tanh in between. That is why its memory can last.

🎓 Detailed: the full LSTM equations ([h, x] = the two vectors glued together; ⊙ = multiply element by element) f_t = σ( W_f · [h_(t−1), x_t] + b_f ) forget gate i_t = σ( W_i · [h_(t−1), x_t] + b_i ) input gate g_t = tanh( W_g · [h_(t−1), x_t] + b_g ) candidate o_t = σ( W_o · [h_(t−1), x_t] + b_o ) output gate c_t = f_t ⊙ c_(t−1) + i_t ⊙ g_t h_t = o_t ⊙ tanh( c_t ) Four weight matrices instead of one: that is the "4× the parameters". In PyTorch they are stored stacked in weight_ih_l0 (shape 4·H × E) and weight_hh_l0 (4·H × H). A common trick: start the forget-gate bias at +1, so the cell remembers by default.

🪶 The lighter cousin: GRU (2014)

A GRU (gated recurrent unit) has only 2 gates: an update gate (how much old memory to keep vs. replace: forget and input in one) and a reset gate (how much of the old memory to use when making the new candidate). No separate cell state. About 3× an RNN's weights instead of 4× (18,816 vs 25,088 at our sizes), often just as good. In PyTorch it is one word: nn.GRU.

🔎 Why is accuracy so high, and why can't we trust it here?

🛂 Think of airport security. 1,115 passengers walk through, and 155 of them carry something forbidden. A lazy guard waves everybody through. He is "right" about the 960 innocent passengers, so he is 86% correct, and he catches nobody. Accuracy gives him a point for every easy "you're fine". The real question is: of the 155, how many did you stop? That question is called recall.

🐍 The model in PyTorch

import torch.nn as nn

class TextClassifier(nn.Module):
    def __init__(self, vocab_size, emb_dim=32, hidden=64):
        super().__init__()
        self.emb  = nn.Embedding(vocab_size, emb_dim, padding_idx=0)  # word id → 32 numbers
        self.lstm = nn.LSTM(emb_dim, hidden, batch_first=True)        # nn.RNN / nn.GRU: same call
        self.out  = nn.Linear(hidden, 2)                              # 2 scores: ham, spam

    def forward(self, x):                                             # x: (batch, 40) word ids
        output, (h_n, c_n) = self.lstm(self.emb(x))                   # output: (batch, 40, 64)
        return self.out(output[:, -1])                                # memory after the LAST word

batch_first=True means tensors are (batch, time, features). For nn.RNN and nn.GRU the second output is just h_n, not a pair, so write output, _ = ... to cover all three.

⑥ From RNN to Transformers to today's LLMs

  1. 1986RNN, backprop through time (Rumelhart, Hinton & Williams): a network with a memory loop.
  2. 1997LSTM (Hochreiter & Schmidhuber): gates + cell state fix the fading memory.
  3. 2014GRU & seq2seq: one RNN reads a sentence, a second RNN writes the translation.
  4. 2014–15Attention (Bahdanau et al.): while writing each word, the translator may look back at any input word instead of one squeezed memory.
  5. 2017Transformer, "Attention Is All You Need" (Vaswani et al.): no recurrence at all. It reads all words at once, in parallel, and attention lets every word look at every other word.
  6. 2018BERT & GPT: big Transformers pretrained on huge amounts of text, then fine-tuned (transfer learning, Lesson 11, for text).
  7. 2020GPT-3: 175 billion weights; can do new tasks from a few examples in the prompt.
  8. 2022ChatGPT: a Transformer tuned to follow instructions and chat.
  9. todayLLMs such as Claude, GPT, Gemini and Llama: all Transformers at heart.

🚀 Why Transformers replaced RNNs

  • Parallel training. An RNN must finish word 1 before word 2. A Transformer handles all words at the same time, which is exactly what GPUs are good at. So it can be trained on far more text.
  • No fading memory. Word 500 can look straight at word 2. No long chain of multiplications in between.

🔋 Where RNNs are still useful

  • Small data and small devices: a few thousand weights, runs on a phone or a microcontroller.
  • Streaming: sensor data, audio, live keyboards. An RNN keeps a fixed-size memory and does the same small work per new sample, forever. A Transformer's cost grows with the length of the text.

Attention cost grows with (length)², so very long inputs are expensive. That's why newer "state-space" and linear-attention models (e.g. Mamba, RWKV) bring some RNN ideas back.

🤔 Check yourself

  1. An RNN reads a 40-word message. How many sets of weights (W, U, b) does it have: 1 or 40?
    AnswerOne. The same cell is reused at every step. That's why it can read texts of any length.
  2. What does the forget gate do when its value is 0? And when it is 1?
    Answer0 = erase the old cell state completely. 1 = keep it exactly as it was. Values in between keep a part of it.
  3. Why does the notebook pad messages with zeros at the front, not at the end?
    AnswerThe Linear layer only uses the memory after the last step. With padding at the end, the model would read 20 empty slots after the real words, and the real words would fade from its memory.
  4. The lazy "always ham" model has 86.1% accuracy. Why is it useless, and which number shows it?
    AnswerIt never catches any spam: spam recall = 0%. Because most messages are ham, accuracy looks high anyway (Lesson 9: imbalanced data).
  5. In the squares, pick plain RNN and switch between Accuracy and Spam recall. How many red squares are there in each view, and why are the two percentages so different?
    Answer24 red squares in both views: the same 24 spam messages got through. Accuracy divides all 33 mistakes (24 red + 9 orange) by 1,115 messages: 3.0% wrong. Recall divides the 24 missed spam by only the 155 spam: 15.5% missed. Same mistakes, smaller total, bigger share.
  6. Give two reasons why Transformers replaced RNNs for large language models, and one case where an RNN is still a good choice.
    Answer(1) All words are processed in parallel, so training on GPUs is much faster. (2) Attention links any two words directly, so nothing fades over long texts. RNNs are still good for small models on small devices and for streaming data (sensors, audio), where they do a fixed small amount of work per new sample.
