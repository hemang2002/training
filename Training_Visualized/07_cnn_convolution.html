How a CNN sees

A convolution slides a tiny 3×3 stencil (the kernel) over the image. At every position it multiplies, adds up, and writes one number. Different stencils light up different patterns: edges, corners, blobs. A CNN learns the stencil numbers with gradient descent.

🧸 Think of it like this

Imagine scanning a picture with a tiny 3×3 magnifying glass that only lights up when it sees one particular pattern, for example a vertical edge. Slide it over the whole picture and you get a new picture showing where that pattern is.

👀 Notice this

Different kernels find different things: edges, corners, blobs. A CNN learns its own kernels. Nobody designs them by hand.

🧮 The one-number recipe

  1. Place the 3×3 window on the image (top-left first).
  2. Multiply each of the 9 pixels by the kernel number in the same spot.
  3. Add the 9 products (plus a bias, 0 here). That's one output number.
  4. Slide by the stride (1 or 2 pixels) and repeat until the whole image is covered.
  5. ReLU sets negative outputs to 0. Max-pool keeps the largest value in every 2×2 block, halving width and height.

output size = ⌊(input + 2·padding − kernel) / stride⌋ + 1

🗂️ 2. Many kernels = many channels

A real conv layer applies many kernels to the same input. nn.Conv2d(1, 6, kernel_size=3) has 6 kernels and produces 6 feature maps (called channels). Below: six hand-made kernels on your drawing (conv + ReLU, padding 1). In a trained CNN nobody hand-makes these; the numbers are learned by backprop, exactly like w and b in Lesson 3.

👀 Six different 3×3 kernels on the same drawing. Each one lights up a different kind of detail. A real CNN learns dozens of these by itself.

💰 3. Why not just use a normal (dense) layer?

A conv layer reuses the same small kernel at every position (weight sharing) and only looks at nearby pixels (local connectivity). That is why CNNs need far fewer parameters and why a cat is recognised whether it sits on the left or the right of the photo.

🧪 Try this

  1. Edge detectors. Draw (or pick) the digit 1 and choose "Vertical edges". Then "Horizontal edges". Which parts light up?
    AnswerVertical edges: the left and right sides of the stroke respond (blue on one side, orange on the other, because this Sobel kernel computes "right minus left"). Horizontal edges respond at the top and bottom ends. With ReLU on, only one side (the positive one) survives. The first layer of a trained CNN typically learns kernels just like these.
  2. Predict the size. Before changing anything, compute the feature-map size for padding 1, stride 2 using the formula. Then check.
    Answer⌊(28 + 2 − 3) / 2⌋ + 1 = ⌊27 / 2⌋ + 1 = 14. With max-pool 2×2 it becomes 7×7. Padding 0, stride 1 gives 26×26: the border shrinks by one pixel on each side, because the window can't be centred on the edge pixels.
  3. Build your own. Make a kernel that detects a horizontal line but ignores vertical ones. Test it on the "+" shape.
    AnswerFor example rows [−1 −1 −1], [2 2 2], [−1 −1 −1]. On a horizontal bright line the middle row gives a big positive sum. A vertical line touches one pixel in each row, the middle column, so it gets −1 + 2 − 1 = 0. The numbers in a kernel sum to 0 here, so flat areas give 0 too.
  4. Blur vs sharpen. Try Blur and Sharpen on a digit, with ReLU off. What does the sum of the kernel's 9 numbers tell you?
    AnswerBlur's numbers sum to 1 (average of the neighbourhood), and Sharpen's also sum to 1 (5 − 4), so flat areas keep their brightness. Edge kernels sum to 0, so flat areas become 0 and only changes light up.
  5. Pooling = forgiving position. Draw a small dot, note which pooled cell lights up, then move the dot by one pixel.
    AnswerOften the same pooled cell still lights up, because max-pool keeps the strongest value in each 2×2 block. Small shifts don't matter much. That's part of why CNNs are robust to where exactly an object appears.
  6. Parameter shock. In the calculator, set the image to 224 (ImageNet size), 3 input channels, 64 kernels. Compare the two layers.
    AnswerConv: (3·3·3 + 1)·64 = 1,792 parameters. A dense layer producing the same 224·224·64 outputs from 224·224·3 inputs would need about 483 billion parameters, which is impossible to train or even store. Weight sharing is what makes deep learning on images possible.

🐍 Your Day-1 CNN, decoded

nn.Conv2d(1, 32, kernel_size=3, padding=1), nn.ReLU(),    # 32 learned 3x3 kernels: 1x28x28 -> 32x28x28   (320 params)
nn.MaxPool2d(2),                                    # 32x28x28 -> 32x14x14                             (0 params)
nn.Conv2d(32, 64, kernel_size=3, padding=1), nn.ReLU(),   # each kernel is 32x3x3: -> 64x14x14            (18,496 params)
nn.MaxPool2d(2),                                    # -> 64x7x7
nn.Flatten(),
nn.Linear(64 * 7 * 7, 128), nn.ReLU(),                  # 3136 -> 128                                  (401,536 params)
nn.Linear(128, n_classes)                            # 128 -> 10                                    (1,290 params)

Note: the two conv layers together have fewer than 19,000 parameters, while the first Linear layer alone has 401,536. Most parameters in small CNNs live in the dense "head". That's also why Day 2's dynamic quantization (which targets Linear layers) still shrinks CNNs. PyTorch's Conv2d computes exactly the multiply-and-add shown on this page (technically cross-correlation: the kernel is not flipped).

🤔 Check yourself

  1. A 3×3 kernel on an RGB image: how many numbers does one kernel contain?
    Answer3 × 3 × 3 = 27 weights (plus 1 bias). A kernel always spans all input channels.
  2. Why do deeper layers "see" bigger patterns even though each kernel is only 3×3?
    AnswerEach layer looks at a 3×3 patch of the previous feature map, and pooling shrinks the map. So one value deep in the network depends on a large area of the original image (its receptive field). Edges → corners → parts → objects.
  3. What does the network learn during training in a conv layer?
    AnswerOnly the kernel numbers and biases. The sliding, multiplying and pooling are fixed operations.
