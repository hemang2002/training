  • Zeros are still numbers. In float32 a 0 takes 4 bytes. Zipping helps the download only; in memory the model is full size again.
  • × 0 costs as much as × 0.37. The CPU multiplies whole blocks and never checks for zeros.
  • A sparse list backfires at medium sparsity: every kept weight also needs its position, and jumping around memory is slow.
  • Global vs per-layer. Day 2's prune.global_unstructured ranks all weights together; per-layer is safer but less clever.
  • Which channel is weakest? L1 norm of its weights, or its BatchNorm γ ("network slimming").
  • Channels are chained. Removing an output channel removes an input of the next layer; residual connections force matching sizes (the notebook prunes only inner channels; torch-pruning tracks this).
  • Iterative: prune a little → retrain → repeat. 2:4 sparsity needs NVIDIA sparse tensor cores (A100 / RTX 30xx+).

👀 Short bars are good. Time bars use a log scale. Latencies are medians on one laptop: compare ratios.
  • ONNX Runtime alone: 8.8 → 1.3 ms, same weights. A fused, pre-planned graph beats Python overhead.
  • Static int8 (calibration, per-channel): 3.5× smaller and fastest (0.9 ms), −0.6 pp. This is what Day 3 serves.
  • Dynamic int8 in PyTorch only rounds the last Linear layer, so a CNN barely changes (9.15 MB, slower).
  • FP16: half the size, no CPU speed-up. BF16: ≈ 26× slower (no BF16 hardware, emulated).
  • Unstructured pruning: same size, same speed; 50% without retraining collapses to 33%.

📏 Detailed: the rounding formula

Find the layer's range (say −0.4 … +0.4), put 255 evenly spaced marks on it, and store only the number of the nearest mark (an int from −127 to 127, 1 byte).

q = round(x / scale) + zero_point
x̂ = (q − zero_point) × scale

scale = spacing between marks. zero_point = which integer means 0.0 (0 for symmetric). x − x̂ is the quantization error. Real int8 picks the range per tensor or per channel, from the weights (and, for activations, from calibration data).

🧪 Trainer challenges (guess first, then check)

  1. In ②, go from 1 bit up. When are the red lines too small to see?
    Answer1 bit: 2 values, mistake ≈ 0.57. Each bit doubles the values and roughly halves the mistake (2 bits ≈ 0.17, 4 ≈ 0.04, 8 ≈ 0.002). From about 6 bits the lines vanish. Photo: 8–6 bits look identical, stripes from 4–5 bits, 1 bit = 6 colours.
  2. In ④, lower the bits one step at a time. When does After break?
    AnswerFine down to 4 bits (≈ 97%), 3 bits ≈ 88%, 2 bits ≈ 51% (only −, 0, +). Per-channel: 3 bits ≈ 96%, 2 bits ≈ 80%.
  3. Cut 50% smallest vs 50% random.
    AnswerSmallest: still ≈ 97% (only faint lines go). Random: ≈ 54%, important thick lines were cut too.
  4. Cut 90% (smallest), then 🔧 Retrain.
    Answer≈ 51% right after cutting; retraining brings it back to ≈ 98% with only 112 of 1,120 weights. The size does not shrink: zeros are still stored.
  5. 🧱 Remove 50% of the neurons, then 75% + 🔧.
    Answer50%: 93%, layers 32 → 16, file 4.63 KB → 1.32 KB, 1,120 → 304 multiplications. 75%: breaks (67%), retrained back to 98% with 88 multiplications (13× less work).
  6. In ⑤ at 50%: ✂️ vs 🧱. Then 📇 sparse list from 30% up.
    Answer✂️ keeps 87% strength but stores 384 B and does all 96 multiplications (48 × 0). 🧱 stores 192 B, 48 multiplications, keeps 74%. Sparse list: 30% → 572 B, 50% → 420 B (bigger!), from 60% (340 B) smaller, 90% → 116 B.
  7. In ⑥, the 4-neuron students, then 2 neurons.
    Answer4 neurons (17 weights): 20 labels only 74.5%; copying the teacher on 1,000 unlabelled dots 98% (teacher 97%). 2 neurons: 77.5% vs 82%: too small to learn the border.
  8. Calibration: ❌ 3 examples, ❌ wrong preprocessing, then wrong preprocessing at 8 bits.
    Answer3 examples: 1.5% clipped, 97% → 75.5%. Wrong preprocessing at 4 bits: ruler 6× too long → 87%. At 8 bits it's hidden (97.5%), but still a bug. Day 2 Lab Ex. 3: forgotten Normalize dropped int8 from ≈ 90% to ≈ 30%.
  9. 4,000 weights: at 8 bits add ONE outlier, then clip at 99.9%.
    AnswerThe ruler gets ≈ 5× wider, SQNR 42 → 28 dB, 4× more weights round to 0. Clipping restores the fine ruler for the 3,999 normal weights (overall SQNR ≈ 13 dB because the outlier's error is huge). About 6 dB per bit.
  10. Per-channel: the std 0.01 channel at 8 and 4 bits.
    AnswerPer-tensor: poor SQNR (near 0 dB at 4 bits). Per-channel gives every channel similar good SQNR, which is why Day 2 used per_channel=True.

🤔 Quick quiz

  1. 32 bits ➜ 8 bits. How much smaller?
    Answer4× smaller, and the accuracy barely moves.
  2. ✂️ Cut the smallest weights or 🎲 random ones?
    AnswerThe smallest: a small weight has a small effect.
  3. You set half the weights to 0. Is the file smaller?
    AnswerNo. Zeros are still stored. 🧱 Remove whole neurons to really shrink it.
