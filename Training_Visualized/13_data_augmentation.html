Data augmentation: more pictures for free

A model with only a few pictures starts to memorise them, pixel by pixel. Data augmentation shows the same picture in new ways: flipped, shifted, zoomed, a bit darker, a bit blurry. Every epoch the model sees a slightly different version, so it has to learn what matters (ears, whiskers, shape) instead of the exact pixels. The one rule: after the change, the label must still be true.

👋 New here? The 30-second version

🧸 Think of it like this

If you only ever saw one photo of your new classmate, you might not recognise them in the shade, from the side, or wearing a hat. Seeing them on many different days teaches you their face, not that one photo. Augmentation gives the model "many different days" from one photo.

👀 Notice this

Without augmentation, training accuracy goes to ≈ 100% but new pictures do worse (overfitting). Good augmentation makes training harder, and the model does better on new pictures. Too much makes it fail everywhere.

📖 Hard words, made easy:
Augmentation = making new versions of a training picture Transform = one change, like "flip" or "rotate"Label = the right answer for a picture ("cat") Overfitting = memorising the training pictures instead of learningValidation set = pictures kept aside to test on Epoch = one pass over all training picturesColour jitter = small random changes of light and colour Cutout (random erasing) = cover a random box with grey

① Why augment?

A neural network has millions of weights. If it only has a few thousand pictures, it can simply remember each one: "this exact pattern of pixels = cat". That works on the training pictures (≈ 100%!) but fails on new ones. This is overfitting (Lesson 7).

The fix that costs nothing: every time a picture is used, change it a little, at random. The cat is flipped, then zoomed in, then a bit darker. The exact pixels are never the same twice, so memorising them doesn't help. The only way to be right every time is to learn what a cat looks like.

🎁 More variety, no new photos, no new labels. On a small dataset this is often the cheapest big win you can get.

⑤ Rules to remember

  

    
🏋️ Only on training data
Validation and test pictures get no random changes: only resize + normalise. We want to measure the model on real, clean pictures, and the same way every time.

    
🎲 Fresh every epoch
The changes are random and made when a picture is loaded. Epoch 1 and epoch 2 see different versions. The dataset on disk does not grow.

    
🏷️ Label stays true
Only use changes that could really happen and don't change the answer. Think about your data: digits, text, colours, medical scans all have their own rules.

    
💸 Cheap and strong
No new photos, no new labels, a little extra CPU work. Biggest help when data is small. Start gentle; too strong = underfitting.

🐍 Detailed: train and test pipelines in PyTorch

  
from torchvision import datasets, transforms
mean, std = (0.4914, 0.4822, 0.4465), (0.2470, 0.2435, 0.2616)   # CIFAR-10

train_tf = transforms.Compose([
    transforms.RandomCrop(32, padding=4),          # shift by up to 4 pixels
    transforms.RandomHorizontalFlip(),
    transforms.ColorJitter(0.2, 0.2, 0.2),
    transforms.ToTensor(),
    transforms.Normalize(mean, std),
])
test_tf = transforms.Compose([                        # NO random changes here
    transforms.ToTensor(),
    transforms.Normalize(mean, std),
])
train_ds = datasets.CIFAR10("data", train=True,  transform=train_tf)   # still 50,000 files
test_ds  = datasets.CIFAR10("data", train=False, transform=test_tf)
# train_tf runs inside __getitem__, so every epoch draws new random versions

  
🔮 Test-time augmentation (TTA)

  
A trick for the final prediction, not for measuring during training: predict on the test picture and on a few gentle versions of it (e.g. flipped),
  then average the probabilities. It often adds a little accuracy, but it costs several forward passes per picture. Use the same gentle, label-safe transforms.

  
probs = (model(x).softmax(1) + model(x.flip(3)).softmax(1)) / 2   # original + horizontal flip

  
More ideas you will meet later: AutoAugment / RandAugment (a learned or random list of transforms), Mixup / CutMix (blend two pictures and their labels).
  In RandomResizedCrop(scale=(a, 1)), a is the smallest share of the picture's area that is kept.






  
🧪 Try this (guess first, then check!)

  
    
    
  1. How far is too far? In ②, press 👍 Gentle, then drag Random crop all the way up and Rotation to 45°. Press 🎲 a few times. Is every picture still clearly a cat?
      
    AnswerNo. Some crops show only grass, the ball or half an ear, and big rotations leave large black corners. Those pictures still carry the label "cat",
      so the model is taught something false. Keep crops big enough that the object stays in the picture (e.g. keep ≥ 60–80% of the area) and rotations small (≈ 10–15°).
    2. 
    
  2. Higher is not always better. In ④, compare 🚫 No augmentation with 👍 Good. Which one has the higher training accuracy? Which one would you ship?
      
    AnswerNo augmentation reaches ≈ 99% on training pictures, but only ≈ 65% on new ones. Good augmentation stays lower on training (≈ 87%)
      but reaches ≈ 81% on new pictures. Ship the one with the better validation accuracy. Training accuracy only tells you how well it remembers.
    3. 
    
  3. Everything at maximum. In ②, press 💥 Too strong and look at the batch. Which curve in ④ do you expect?
      
    AnswerThe 💥 curve: both training and validation stay low (≈ 50%). The pictures are so damaged that the model can't even learn the training set:
      underfitting. Validation is even a bit higher than training, because validation pictures are clean. Turn the strength down until training accuracy rises again.

🤔 Check yourself

  
    
    
  1. Why do we not augment the validation and test pictures?
      
    AnswerThey are there to measure how good the model is on real pictures. Random changes would make the score noisy (different every run) and test on pictures that don't really exist.
      They get only the same resize + normalise as training.
    2. 
    
  2. You have 1,000 training pictures and train for 20 epochs with augmentation. How many pictures are on disk after training? How many different versions did the model see?
      
    AnswerStill 1,000 on disk: augmentation never saves new files. But the model saw 20 × 1,000 = 20,000 pictures, and almost all of them were different random versions.
    3. 
    
  3. Your model tells a left hand from a right hand. Is RandomHorizontalFlip a good idea?
      
    AnswerNo! A mirrored left hand looks exactly like a right hand, so the label would become wrong. Same problem as the "turn left" sign in ③.
    4. 
    
  4. With your new augmentation, training accuracy is 58% and validation 60%, and both stopped improving. What is going on, and what do you try?
      
    AnswerUnderfitting: the augmentation is probably too strong (or the model too small). Make the changes gentler, then maybe train longer or use a bigger model.
      You want training accuracy a bit above validation, with a small gap.
