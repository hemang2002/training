What is a model?

A model is a formula with knobs. Training means turning the knobs until the formula's guesses are good. Today you are the training algorithm.

👋 New here? The 30-second version

🧸 Think of it like this

A guessing game. You tell me the temperature, and I guess how many ice-creams the shop will sell. My guessing rule has two dials. At first my guesses are bad. I turn the dials until my guesses get close. That's all "training" means.

🍦 The story: an ice-cream shop

An ice-cream shop wrote down, for 20 days, the temperature and how many cups they sold. The owner wants to guess tomorrow's sales from the weather forecast.

We guess that sales grow in a straight line with temperature, so our model is:

cups = w × temperature + b

  • w (the weight): how many extra cups we sell for each extra degree.
  • b (the bias): where the line starts, i.e. sales at 0 °C.
  • w and b are the model's parameters: the knobs. The model's "knowledge" is just these numbers.
  • A big neural network has the same idea with millions of knobs. ResNet-18 has 11.7 million; our Day-2 MobileNetV2 has 2.2 million.

📏 MSE, RMSE or MAE? Three ways to measure "wrong"

All three start the same way: for every day, take the error = guess − real value (the red dashed line). They only differ in how they add the errors up.

MSE Mean Squared Error

MSE = ( error₁² + error₂² + … + errorₙ² ) ÷ n

In maths: MSE = (1/n) · Σ (ŷᵢ − yᵢ)²  (ŷ = guess, y = real value, n = number of days)

Square each error, then take the average. Squaring makes big errors much bigger: an error of 2 counts as 4, but an error of 20 counts as 400.

RMSE Root Mean Squared Error

RMSE = √MSE

In maths: RMSE = √( (1/n) · Σ (ŷᵢ − yᵢ)² )  (√ = square root)

Just MSE with a square root on top. This undoes the squaring of the unit, so the answer is back in cups, not cups². Big errors still count extra, just like MSE.

MAE Mean Absolute Error

MAE = ( |error₁| + |error₂| + … + |errorₙ| ) ÷ n

In maths: MAE = (1/n) · Σ |ŷᵢ − yᵢ|  (|…| = drop the minus sign)

Drop the minus sign from each error, then take the average. An error of 20 counts as 20, exactly 10× an error of 2. Fair to every error.

🧭 When to use which

Use MSE when…

  • Big mistakes are really bad and must be avoided. Being off by 20 is far worse than being off by 2 ten times (e.g. a medicine dose, a bridge load).
  • Your data is clean, with no strange one-off points.
  • You don't know what to pick: MSE is the usual default for predicting numbers. Its smooth curve also gives gradient descent nicely shrinking steps near the best answer.

Use RMSE when…

  • You want MSE's "big mistakes are bad" behaviour, but need to show the number to people: "off by about 10 cups" is easy to understand.
  • You are reporting results (charts, reports, comparing models). RMSE is one of the most common scores you will see.
  • Training tip: the best line for RMSE is the same as for MSE (the root doesn't change which line wins), so we usually train with MSE and report RMSE.

Use MAE when…

  • Your data has outliers (festival days, typos, broken sensors) that you don't want the model to chase.
  • Every mistake is equally bad per cup: being off by 20 is just 10× as bad as being off by 2.
  • You want a number that is easy to explain: MAE is in the same unit as the data ("6.5 cups"). MSE is in cups², which means little to a shop owner.
👀 See it yourself: tick Add a festival day above, press 🤖 with MSE, then switch to MAE and press 🤖 again. The MSE line gets pulled towards the festival day; the MAE line mostly ignores it.

In PyTorch: nn.MSELoss() for MSE, torch.sqrt(nn.MSELoss()(pred, y)) for RMSE, nn.L1Loss() for MAE. A popular middle ground is nn.HuberLoss(): it acts like MSE for small errors and like MAE for big ones.

🧪 Try this (predict first, then check!)

  1. Beat the goal. Reach the green banner using only the sliders. How many knob moves did you need? Now imagine doing this for 11 million knobs.
    Why this matters With 2 knobs you can "feel" your way to a good answer. With millions of knobs, guessing is hopeless. We need a method that tells us which direction to turn every knob at once. That method is the gradient (Lessons 2 and 3).
  2. Why is the best loss not zero? Set Noise to 0 and press 🤖. What loss do you get now?
    Answer With zero noise the points lie exactly on a line, so the loss can reach (almost) 0. Real data has noise: things the model does not know about (holidays, a football match, a broken freezer). No model can predict noise, so the best possible loss is above zero.
  3. MSE vs MAE and the outlier. Tick Add a festival day. Press 🤖 in MSE mode, then switch to MAE and press 🤖 again. Which line gets pulled towards the festival day more?
    Answer MSE squares the errors, so one error of 100 counts like 100 errors of 10. The MSE line bends towards the outlier. MAE counts every error just by its size, so it mostly ignores the one weird day. Choosing the loss is a design decision: it defines what "good" means.
  4. The shape of the landscape. Look at the right-hand chart. Is the dark valley round or a long thin diagonal? Click different places inside it and watch the line.
    Answer It is a long, thin, diagonal valley. If you make w bigger, you can make b smaller and get almost the same line in the middle of the data, so the two knobs "fight" each other. Long thin valleys are hard for gradient descent, which is why we normalize inputs (Day 1 notebook, transforms.Normalize). The 🤖 button secretly normalizes the temperature before fitting.
  5. Small data is unreliable. Set days = 5, noise = 25, then press 🎲 several times and reveal the best line each time.
    Answer With 5 noisy points the "best" line jumps around a lot between datasets. With 60 points it hardly moves. More data gives a more trustworthy model. We come back to this in Lesson 7 (overfitting).

🐍 The same thing in PyTorch

import torch, torch.nn as nn

model = nn.Linear(1, 1)             # cups = w * temp + b ; w and b start random
print(model.weight, model.bias)     # the two knobs (parameters)

loss_fn = nn.MSELoss()              # or nn.L1Loss() for MAE
temps = torch.tensor([[21.0], [30.5], [35.2]])   # shape (N, 1)
cups  = torch.tensor([[44.0], [70.0], [88.0]])
pred  = model(temps)                # predictions
loss  = loss_fn(pred, cups)         # one number: how wrong we are
print(loss.item())

In Lesson 4 we add the three lines that let PyTorch turn the knobs for us: zero_grad(), backward(), step().

🤔 Check yourself

  1. Which numbers change during training: the data, or the parameters?
    AnswerOnly the parameters (w, b). The data stays fixed.
  2. Your loss is 0.0 on the 20 days you have. Does that guarantee good predictions for tomorrow?
    AnswerNo. It only says you fit these days. Tomorrow is new data. We must always measure on data the model has never seen (a validation or test set). See Lesson 7.
  3. Why do we need one number (the loss) instead of looking at all 20 errors?
    AnswerTo compare two settings of the knobs we need to say "this one is better". One number can be compared; 20 separate errors cannot (one might go up while another goes down).
