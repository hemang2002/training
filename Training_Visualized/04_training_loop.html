The training loop, one line at a time

Every PyTorch training script, from this toy up to GPT, has the same six-line heartbeat: take a batch → predict → measure the loss → clear old gradients → backpropagate → step. Here you can run it one line at a time and watch what each line does.

👋 New here? The 30-second version

🧸 Think of it like this

Learning with flashcards. Take a few cards, answer them, check the answers, learn from your mistakes, then take the next few cards. When you have been through all the cards once, that is one epoch. Then shuffle and start again.

Each step uses only a few dots (the ringed ones). That's a batch. The loss chart goes down as the model learns.

🎯 The task

Each dot is a student. The x-axis is hours studied and the y-axis is hours slept (both rescaled). Orange = failed, blue = passed. The model is logistic regression: a line that separates the two colours. It has three knobs: w₁, w₂ and b. It outputs a probability p = sigmoid(w₁·x₁ + w₂·x₂ + b) that the student passes. 🎛️ Settings & bug switches

🐞 Bug switches (classic mistakes)

Changing a setting restarts training from the same starting knobs, so comparisons are fair.

📖 Words you now know

Batch (mini-batch)A small group of samples used for one step. The gradient from a batch is a cheap, slightly noisy estimate of the gradient on all data.
Iteration / stepOne pass through the inner loop: one batch, one optimizer.step().
EpochOne full pass over the whole dataset. Iterations per epoch = ⌈N / batch size⌉.
zero_grad()PyTorch adds new gradients to .grad instead of replacing them. So you must clear them before every backward pass.
shuffle=TrueMixes the order of samples every epoch, so every batch looks like a fair sample of the data.

🧪 Try this

  1. Count first. 32 samples, batch size 8: how many iterations in one epoch? And with batch size 1? And 32? Check with "Next epoch".
    Answer4, 32 and 1. With batch size 32 the "mini-batch" is the whole dataset: that is plain (full-batch) gradient descent from Lesson 2. In Day 1's FashionMNIST notebook: 60,000 images at batch size 64 gives 938 iterations per epoch (the last batch has only 32 images).
  2. Noisy vs smooth. Run 20 epochs with batch size 1, then with batch size 32 (tip: set Run speed to "One epoch per tick"). Compare the grey per-iteration loss curves and the number of iterations.
    AnswerBatch size 1: 640 tiny, noisy steps. Each one follows a single student, so the line jitters. Batch size 32: 20 smooth steps. Small batches give more updates per epoch but noisier ones; large batches give fewer, more accurate updates (and use the GPU better). Typical real values are 32–256.
  3. Bug: no zero_grad. Tick "I forgot zero_grad()" and run. Watch the gradient bars and the line.
    AnswerThe gradients never reset, because every backward pass adds to the old ones. Each step then uses the sum of all previous gradients, so the line overshoots and swings back and forth. With the default settings the loss on all data gets worse epoch after epoch (≈ 0.24 after epoch 1, ≈ 1.0 after epoch 20), while the correct loop goes down to ≈ 0.22. There is no error message; the code "runs fine". This is one of the most common silent bugs in PyTorch.
  4. Bug: no shuffle. Batch size 1, learning rate 2. Run 20 epochs with shuffle, then tick "I forgot shuffle=True" and run again. Compare the final loss and the "Model says pass" counter (16 students truly passed). Finally set batch size 32 with the bug still on.
    AnswerWith shuffle: final loss ≈ 0.21 and the model says "pass" for 17 students. Without shuffle the model sees 16 orange students in a row, then 16 blue ones, so the line swings back and forth every epoch. Each epoch ends after a long run of blue, so the final model says "pass" for 22 students and its loss is ≈ 0.49, more than twice as bad. With batch size 32 the bug has no effect at all (identical numbers), because every batch contains all the data and the order inside a batch doesn't matter. Real datasets are often stored sorted by class (a folder per class), which is why shuffle=True matters.
  5. One batch vs everything. In line-by-line mode, note the batch loss at the loss = line, finish the step, and compare with "Loss on all data". Does one step always improve the loss on all data?
    AnswerNot always. A step is chosen to help this batch, and it can slightly hurt other samples. On average, over many batches, the loss on all data goes down. That is why we judge training by the per-epoch curve, not by single steps.

🐍 The full script (run it on Day 1)

import torch, torch.nn as nn
from torch.utils.data import TensorDataset, DataLoader

X = torch.randn(32, 2); Y = (X[:, 0] + X[:, 1] > 0).float().unsqueeze(1)   # toy data
loader = DataLoader(TensorDataset(X, Y), batch_size=8, shuffle=True)

model = nn.Linear(2, 1)                                   # w1, w2, b
loss_fn = nn.BCEWithLogitsLoss()                          # sigmoid + log-loss in one, numerically stable
optimizer = torch.optim.SGD(model.parameters(), lr=0.5)

for epoch in range(20):
    for xb, yb in loader:
        pred = model(xb)
        loss = loss_fn(pred, yb)
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
    print(epoch, loss.item())

Two more lines appear in real scripts: model.train() before the loop and model.eval() + torch.no_grad() for validation after each epoch. They matter for Dropout and BatchNorm, which this tiny model doesn't have.

🤔 Check yourself

  1. Why is zero_grad() placed before backward() and not after step()? Does it matter?
    AnswerEither placement works as long as the gradients are cleared once between two backward passes. "Before backward" is the safest habit, because it also clears anything left over from earlier code.
  2. Why would anyone want gradients to accumulate?
    AnswerGradient accumulation: if a batch of 256 doesn't fit in GPU memory, run 4 batches of 64 with backward() each, then step() and zero_grad() once. You get the same update as one batch of 256. So the "bug" is sometimes a feature, when it's done on purpose.
  3. You have 1,000 images and batch size 100. After 30 epochs, how many times has optimizer.step() run?
    Answer1,000 / 100 = 10 steps per epoch, × 30 = 300 steps.
